# Пользователи и права платформы

Регистрация выдаёт только `participant`. Параметры `roles`, `role_id`, `is_admin`
в публичной регистрации и изменении профиля отклоняются. Несколько ролей могут
быть назначены одному пользователю через административный API.

## Матрица прав

| Роль | Разрешения | Ограничение области |
|---|---|---|
| admin | Пользователи, роли, разрешения; все разрешения предметных модулей | Назначается оператором сервера или администратором |
| organizer | create-hackathon, manage-hackathon, assign-expert | Изменение только своих мероприятий |
| participant | create-team, join-team, submit-solution | Сдача только капитаном своей команды |
| expert | read-assigned-submission, score-submission | Только назначенные работы |
| Наблюдатель | Публичные данные и leaderboard | Авторизация не требуется |

Капитан — связь пользователя с конкретной командой, а не глобальная роль.
Наблюдателю не нужна запись `guest`. Старые `user` и `guest` сохранены для
совместимости с лабораторной, не назначаются при регистрации и не имеют прав управления.

Проверяются организатор-владелец хакатона, принадлежность кейса, капитан команды
и назначение конкретной сдачи эксперту. Одного наличия permission недостаточно
для доступа к чужому объекту. Не предусмотрен неявный обход этих проверок по
роли администратора. Правила назначений и рейтинга: [SCORING.md](SCORING.md).

## Профиль

- Логин: 3–64 латинские буквы, цифры, `_` и `-`; первый символ — буква или цифра.
- Логин и email уникальны без учёта регистра; вход также не зависит от регистра.
- `display_name`: необязательное отображаемое имя до 128 символов, пробелы по краям убираются.
- `birthday`: необязательная дата; будущие даты отклоняются. Ограничения возраста из лабораторной нет.
- Пароль: не меньше 8 символов с цифрой, строчной/заглавной буквой и спецсимволом;
  максимум 72 байта UTF-8 для bcrypt.
- `PATCH /api/v1/auth/me`: только `display_name` и `birthday`; `null` очищает поле,
  пропущенное поле остаётся прежним. Логин, email, роли и ID этим методом не меняются.
- `GET /api/v1/auth/me`: актуальные роли из БД. Они не зашиты в JWT, поэтому отзыв
  прав применяется на следующем запросе без повторного входа.

## Первый администратор

После запуска Compose:

```bash
docker compose exec api python -m app.bootstrap create-admin --username admin --email admin@example.com
```

Команда запрашивает пароль без вывода на экран и просит повторить его.
Не передавайте пароль аргументом командной строки. Для автоматизации поддержан
`--password-stdin` (одна строка); секрет следует передавать из защищённого источника.

Повторный запуск для того же логина/email и уже назначенной роли ничего не меняет.
Пароль не сбрасывается. Если логин или email занят другим аккаунтом либо роль ему
не назначена, команда завершается ошибкой и не повышает существующему пользователю права.
Это операторская команда с доступом к БД, публичного bootstrap endpoint нет.

## Демонстрационные аккаунты

```bash
docker compose exec api python -m app.bootstrap seed-demo
```

Команда запрашивает общий пароль для локальной демонстрации и создаёт:

| Логин | Email | Роль |
|---|---|---|
| demo-admin | demo-admin@example.com | admin |
| demo-organizer | demo-organizer@example.com | organizer |
| demo-participant | demo-participant@example.com | participant |
| demo-expert | demo-expert@example.com | expert |

Все четыре аккаунта создаются одной транзакцией. Конфликт отменяет всю операцию.
Повторный запуск не меняет пароли и назначения. Команда не запускается автоматически
при старте сервера и не выводит пароль.

## Назначение ролей через Swagger

1. Войти администратором через `/api/v1/auth/login` и нажать Authorize.
2. Получить ID пользователя: `GET /api/v1/admin/user`.
3. Получить ID роли: `GET /api/v1/admin/policy/role`.
4. Назначить: `POST /api/v1/admin/user/{user_id}/role`, тело `{"role_id": 5}`
   (подставить ID из шага 3).
5. Отозвать: `DELETE /api/v1/admin/user/{user_id}/role/{role_id}`.

Организатор, участник и эксперт по умолчанию получают 403 на этих маршрутах.
Администратор может делегировать разрешения; это явная административная операция.
