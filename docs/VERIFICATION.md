Тесты проверяют health/OpenAPI, вход и выход, refresh rotation и повторное
использование токена, подделку refresh без отзыва чужой сессии, запрет повышения
прав обычным пользователем, выдачу/отзыв административного доступа,
неверный пароль/повторную регистрацию и ограничение длины пароля.
Новые проверки: необязательная дата рождения, новый формат логина, имя профиля,
автоматическая роль участника, запрет полей привилегий в регистрации/профиле,
изменение собственного профиля, запрет управления доступом для трёх предметных ролей,
назначение/отзыв эксперта через API, атомарное создание оператором,
невозможность повысить существующего пользователя через bootstrap и повторяемый CLI.

Этап 3: черновики скрыты, незавершённые кейсы блокируют публикацию, проверены
редактирование/удаление кейсов, замена критериев и откат неверного ввода.
Владелец проверяется для всех операций; другой администратор также получает 403.
Проверены даты без часового пояса, UTC-нормализация, порядок дат, диапазоны баллов,
веса, подмена владельца, вложенный ID чужого кейса, пагинация и блокировка изменений
после старта. Границы видимости проверены за микросекунду до старта/дедлайна,
точно в момент старта/дедлайна и после дедлайна без ожидания реального времени.

Этап 4: проверены капитан и состав команды, доступ организатора только к своим
командам, выпуск и отзыв кода, повторное вступление, неверный код, уникальность
названия без учёта регистра, дедлайн командных операций и многоразовое
приглашение. Параллельные запросы одного пользователя на вступление дают один
успех и один 409; в БД остаётся только одна запись членства.

Этап 5: проверены URL и архивы ZIP, лимит 20 МиБ, права капитана, участников и
организатора, запрет анонимного скачивания из MinIO и доступ к файлу через API.
Тесты фиксируют точные границы начала и дедлайна по серверному времени.
При сбое MinIO запись о сдаче не создаётся; при ошибке БД или истечении срока
во время загрузки объект удаляется. Повторная сдача сохраняет историю версий.

Этап 6: организатор назначает эксперта на последнюю сдачу после дедлайна;
эксперт получает только свои назначения и архивы. Проверены диапазоны баллов,
отклонение неверного ID критерия и ручного поля итога, атомарная замена, неполные
оценки, весовая формула, среднее нескольких экспертов, равенство баллов и
пересчёт рейтинга после изменения оценки. Отзыв роли закрывает доступ и
исключает оценку из текущего рейтинга.

Этап 7: события публикации, вступления, сдачи, назначения и полной оценки
записываются в той же транзакции. Тест проверяет получателей, приватность
журнала, прочтение и отсутствие ложного уведомления на отклонённую сдачу.
При ошибке записи уведомления сдача откатывается и архив удаляется из MinIO.
Живой скрипт `scripts/demo_journey.py` повторил сценарий через локальный HTTP API;
его результат `.local/stage7-demo.json` исключён из Git. Выборка p95 — локальная
последовательная проверка, не полноценное нагрузочное испытание.

Starlette выдаёт одно предупреждение об устаревающей интеграции TestClient с HTTPX.
Оно не мешает выполнению тестов; переход тестового клиента учитываем при обновлении зависимостей.

Команды воспроизведения — в README. Далее остаются публикация кода и материалы
мини-отчёта, в том числе скриншоты Swagger.
