# План до первого отчёта

ТЗ: https://yusu-source.github.io/GH_pages/03_hackathon.html

Каждый этап заканчивается воспроизводимой проверкой. Один auth-модуль не покрывает
весь требуемый бэкенд. Предметные этапы выполняем последовательно.

## 1. Основа проекта — готово

- [x] Перенести FastAPI, авторизацию и RBAC из backend-labs/lb3.
- [x] Подключить PostgreSQL, Alembic и `/api/v1`.
- [x] Настроить Compose, автоматические миграции и health endpoint.
- [x] Генерировать локальные секреты, исключить их из Git.
- [x] Описать запуск, структуру и источник кода.
- [x] Проверить чистый запуск и тесты авторизации с PostgreSQL.

Готовность: Swagger открывается, health проверяет БД, вход/refresh/logout работают,
административные операции без прав отклоняются.

Проверено 27.09.2026: Compose поднят на новом томе PostgreSQL, Swagger отвечает 200,
API/БД healthy, 8 интеграционных тестов пройдены; `alembic check` не обнаружил
различий между моделями и миграциями. Код этого этапа пока находится локально.

## 2. Пользователи и права платформы — готово

- [x] Адаптировать профиль и ограничения лабораторной.
- [x] Добавить создание первого администратора и демонстрационных пользователей.
- [x] Описать матрицу прав организатора, участника, эксперта.
- [x] Закрепить правила: капитан управляет своей командой, организатор — своим
      мероприятием, эксперт — назначенными работами.
- [x] Проверить запрет самостоятельного назначения привилегированной роли.

Готовность: настройка пользователей без ручного SQL; тесты прав доступа.
Проверки принадлежности добавляем вместе с соответствующими сущностями.

Проверено: 21 интеграционный тест, обновление существующей БД и чистое развёртывание
тестовой БД; `alembic check` без различий. Созданы локальные `demo-admin`,
`demo-organizer`, `demo-participant`, `demo-expert`. Пароль находится только в
игнорируемом `.local/demo-accounts.json`. Матрица и команды: [ACCESS_CONTROL.md](ACCESS_CONTROL.md).

## 3. Хакатоны, кейсы, критерии — готово (BE-03, часть BE-04)

- [x] Hackathon, Case, Criterion и миграции.
- [x] Создание/изменение организатором, публикация материалов в разрешённый период.
- [x] Начало и дедлайн в UTC, серверное время в API, проверка порядка дат.
- [x] Диапазоны оценок, веса и документированная формула итога.

Готовность: опубликован кейс с критериями; чужой пользователь не редактирует его.

Проверено: 51 тест (включая 30 новых сценариев/вариантов), миграции на чистой
тестовой БД и поверх этапа 2, `alembic check` без расхождений. В локальной БД создан
демонстрационный хакатон ID 1 с кейсом и двумя критериями через HTTP API.
Правила и примеры: [HACKATHONS.md](HACKATHONS.md). Проверка дедлайна самой сдачи
реализуется вместе с Submission на этапе 5; расчёт рейтинга — на этапе 6.

## 4. Команды и приглашения — готово (BE-01, BE-02)

- [x] Team, TeamMember, Invite и миграции.
- [x] Создание команды с капитаном; правила членства в одном хакатоне.
- [x] Генерация/отзыв invite-кода и вступление по нему.
- [x] Проверки повторного/конкурентного вступления и прав капитана.

Готовность: участник вступает по коду; неверный/отозванный код отклоняется.

Проверено 28.09.2026: 61 интеграционный тест (10 новых сценариев команд), миграция
на чистой и существующей PostgreSQL, `alembic check` без расхождений. Через живой
HTTP API создан хакатон ID 2, команда ID 1, код и второй участник. Локальные
демоданные с кодом находятся только в игнорируемом `.local/team-demo.json`.
Подробности: [TEAMS.md](TEAMS.md).

## 5. Решения и MinIO — готово (BE-04–BE-07)

- [x] MinIO в Compose, приватный bucket, секреты в окружении.
- [x] Submission, StoredObject, уникальные object keys; в SQL только метаданные.
- [x] Сдача ссылки и/или архива, ограничения типа и размера.
- [x] Серверные проверки начала/дедлайна и timestamp, правила повторной сдачи.
- [x] Скачивание с проверкой прав; обработка сбоев хранилища.

Готовность: до срока архив сохраняется, после срока сдача отклоняется;
сбой MinIO не оставляет успешную сдачу без объекта; чужой архив недоступен.

Проверено 28.09.2026: 76 интеграционных тестов на PostgreSQL и MinIO,
включая приватный bucket, отклонение сдачи после дедлайна и удаление объекта
при сбое БД или наступлении дедлайна во время загрузки. Подробности:
[SUBMISSIONS.md](SUBMISSIONS.md).

## 6. Эксперты и рейтинг — готово (BE-08–BE-11)

- [x] ExpertAssignment, Score и миграции.
- [x] Назначение экспертов организатором; эксперт видит назначенный пул.
- [x] Баллы только в диапазонах критериев.
- [x] Итог по весам; правила нескольких экспертов и неполных оценок.
- [x] Публичный leaderboard с определённым порядком при равенстве баллов.

Готовность: оценка обновляет рейтинг; чужие работы и некорректные баллы отклоняются;
итог нельзя записать вручную через API.

Проверено 28.09.2026: 85 интеграционных тестов на PostgreSQL и MinIO,
миграция поверх существующей БД, `alembic check` без расхождений. Проверены
назначения, приватные архивы эксперта, диапазоны, полные/неполные оценки,
среднее нескольких экспертов, равенство баллов и отзыв роли.
Правила и API: [SCORING.md](SCORING.md).

## 7. Уведомления и сквозная проверка — готово (BE-12)

- [x] Notification и журнал/тестовый адаптер ключевых событий.
- [x] Демоданные и сценарий на 5–10 минут.
- [x] Полный тест: кейс → команда → сдача → оценка → рейтинг.
- [x] Тесты дедлайна, прав, приватных файлов, сбоев и конкурентных операций.
- [x] Чистое развёртывание, проверка времени ответа обычных запросов.

Проверено 28.09.2026: 87 интеграционных тестов в отдельном Compose-проекте
с новыми томами PostgreSQL и MinIO. Живой сценарий через основной HTTP API
создал хакатон ID 3, команду ID 2, сдачу ID 1 и рейтинг 85.00; поздняя сдача
получила 409, а анонимное скачивание — 401. Результаты без секретов находятся
в локальном `.local/stage7-demo.json`. На 100 последовательных запросах p95:
health 4.2 мс, список хакатонов 5.6 мс, рейтинг 21.8 мс. Инструкция:
[DEMO.md](DEMO.md), события: [NOTIFICATIONS.md](NOTIFICATIONS.md).
