# Сдача решений и хранение архивов

Капитан сдаёт решение по одному из кейсов своего хакатона через
`POST /api/v1/teams/{team_id}/submissions` (`multipart/form-data`):

- `case_id` — обязательный ID кейса;
- `url` — необязательный HTTPS URL;
- `archive` — необязательный `.zip` или `.tar.gz`.

Нужен URL и/или архив. Ссылка не загружается сервером и не исполняется.
Архив ограничен 20 МиБ; проверяются расширение и содержимое. Файлы не
распаковываются и не выполняются приложением. Имя файла очищается от пути.
Ключ объекта генерируется из UUID, не равен имени файла. В PostgreSQL находятся
только размер, SHA-256, имя, тип и ключ объекта; байты хранятся в MinIO.

Сервер принимает сдачи в полуинтервале `starts_at <= server_time < deadline_at`.
После загрузки в MinIO сервер повторно проверяет время и права перед commit.
Если срок вышел, запись в БД не создаётся, объект удаляется. При ошибке БД
после загрузки объект также удаляется. Ошибка MinIO даёт 503 без успешной сдачи.
При повторной сдаче создаётся новая версия; история сохраняется. Список
сортируется по времени и ID, сначала самая свежая. На этапе экспертной оценки
будет использоваться последняя валидная версия на момент дедлайна.

Доступ к сдаче, её истории и скачиванию имеют участники команды и организатор
владельца хакатона с активной ролью. Остальные получают 403. Сам архив можно
скачать только через серверный маршрут с проверкой прав; bucket MinIO приватный.
Код приложения возвращает файл потоком и выставляет `Cache-Control: no-store`.
Экспертам доступ к назначенным работам будет добавлен на этапе 6.

## API

| Метод и путь | Результат |
|---|---|
| POST `/api/v1/teams/{team_id}/submissions` | Создать версию решения (только капитан) |
| GET `/api/v1/teams/{team_id}/submissions?case_id=...` | Список версий, `limit`/`offset` |
| GET `/api/v1/submissions/{id}` | Метаданные версии |
| GET `/api/v1/submissions/{id}/archive` | Приватный архив, если есть |

Swagger: http://localhost:8080/docs. Для демонстрации используйте опубликованный
хакатон, в котором период сдачи уже начался. Даты сравниваются по времени сервера;
тесты проверяют точные границы без ожидания реального времени.

## Локальный запуск MinIO

`docker compose up --build -d --wait` запускает отдельный контейнер MinIO.
Поскольку исторические публичные образы перестали надёжно скачиваться, Compose
собирает бинарник из [официального тега исходного кода](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z)
`RELEASE.2025-10-15T17-29-55Z` через [Dockerfile.minio](../Dockerfile.minio).
Первую сборку может занять время. `storage-init` создаёт приватный bucket.
MinIO Console: http://localhost:9001; логин и пароль задаются `MINIO_ROOT_USER`
и `MINIO_ROOT_PASSWORD` в локальном `.env`, который исключён из Git.
Порт S3 наружу не опубликован; приложение обращается к `minio:9000` внутри Compose.
