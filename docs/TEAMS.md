# Команды и приглашения

Команду может создать пользователь с разрешением `create-team` в опубликованном
хакатоне до дедлайна. Создатель становится капитаном и первым участником.
Один пользователь может состоять только в одной команде одного хакатона:
правило закреплено уникальным ограничением PostgreSQL.

Капитан — статус в конкретной команде, а не глобальная роль. Только капитан
переименовывает команду, выпускает и отзывает приглашение. Код многоразовый до
отзыва или дедлайна; выпуск нового отзывает старый. После дедлайна создание
команды, вступление, переименование и выпуск кода запрещены. Отзыв остаётся доступен.

Код создаётся из 32 криптографически случайных байт в URL-safe base64. В БД
хранится только SHA-256 хэш. Код возвращается один раз при выпуске, затем API
показывает лишь состояние. Состав команды доступен её участникам и организатору
хакатона через отдельные маршруты. Публичного списка участников нет.

Операции изменения блокируют строку хакатона, затем команды, чтобы параллельные
запросы упорядочивались одинаково. После ожидания блокировки сервер снова берёт
текущее время для проверки дедлайна. Уникальные ограничения защищают от гонок.

## API

Все пути начинаются с `/api/v1`.

| Метод и путь | Назначение |
|---|---|
| POST `/hackathons/{id}/teams` | Создать команду, тело `{"name":"Команда А"}` |
| GET `/teams` | Свои команды, `limit`/`offset` |
| GET `/teams/{id}` | Своя команда и участники |
| PATCH `/teams/{id}` | Капитан меняет название |
| POST `/teams/{id}/invite` | Капитан получает новый код один раз |
| GET `/teams/{id}/invite` | Капитан видит статус без кода |
| DELETE `/teams/{id}/invite` | Капитан отзывает код |
| POST `/teams/join` | Участник вступает, тело `{"code":"..."}` |
| GET `/organizer/hackathons/{id}/teams` | Организатор видит команды своего мероприятия |

В таблицах `teams`, `team_members`, `invites` сохранены команда с капитаном,
членство и хэш кода. Составная внешняя связь гарантирует совпадение хакатона
участника с хакатоном команды. Частичный уникальный индекс допускает только
одно активное приглашение команды.

Для проверки в Swagger: войти как `demo-participant`, создать команду в опубликованном
хакатоне, выпустить код и скопировать его сразу. Зарегистрировать второго участника,
войти под ним и вступить по коду. Вернувшись под капитаном, отозвать код и проверить,
что другой пользователь получает 404 при попытке вступить по нему.

Удаление участника и передача капитанства пока не предусмотрены. Сдача решения
появится на этапе 5. Для новой демонстрации организатор может создать опубликованный
хакатон с будущими датами по [инструкции](HACKATHONS.md).
