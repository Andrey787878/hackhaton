# Журнал уведомлений

API сохраняет уведомления в PostgreSQL в той же транзакции, что и предметное
действие. Это локальный журнал и тестовый адаптер: письмо или push не отправляются.
Если транзакция отклонена, уведомления нет. Если запись события не удалась,
предметное действие также откатывается; для архива сервер удаляет уже загруженный
объект из MinIO.

| Событие | Получатель | Ресурс |
|---|---|---|
| `hackathon_published` | Организатор | Хакатон |
| `team_joined` | Капитан | Команда |
| `submission_created` | Организатор | Сдача |
| `expert_assigned` | Эксперт | Назначение |
| `score_completed` | Капитан | Сдача |

Последнее событие создаётся только после полной оценки всех критериев. При её
обновлении оно создаётся снова; неполная оценка уведомления не даёт.
Запись содержит тип, ID ресурса, автора, время и признак прочтения. Секреты,
invite-коды, URL решений и содержимое архива в ней не сохраняются.

Маршруты `/api/v1/notifications` (список с `limit`, `offset`, `unread_only`),
`/api/v1/notifications/unread-count` и
`POST /api/v1/notifications/{id}/read` требуют входа. Пользователь видит и
помечает прочитанными только собственные уведомления; повторная отметка
сохраняет первоначальное время прочтения.
