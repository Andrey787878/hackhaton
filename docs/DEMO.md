# Сквозная демонстрация за 5–10 минут

1. Запустите `python3 scripts/init_env.py` и `docker compose up --build -d --wait`.
   Проверьте `/api/v1/health` и откройте Swagger: http://localhost:8080/docs.
2. Один раз создайте локальные роли командой
   `docker compose exec api python -m app.bootstrap seed-demo` и запомните
   введённый пароль. В существующем окружении демоаккаунты уже созданы.
3. Запустите `python3 scripts/demo_journey.py` из корня проекта. Если есть
   игнорируемый Git файл `.local/demo-accounts.json`, скрипт возьмёт пароль из
   него; иначе запросит пароль без отображения. Скрипт создаёт свежий хакатон
   с близким временем старта и дедлайна и выполняет все вызовы по HTTP API.
4. Пока скрипт ожидает дедлайн, покажите в Swagger опубликованный хакатон,
   кейс, команду, сдачу с серверным временем и закрытый архив. Можно показать
   уведомления организатора и капитана.
5. После дедлайна скрипт проверит ответ 409 на позднюю сдачу, назначит эксперта,
   выставит баллы 8/10 и 5/5 с весами 3 и 1 и проверит итог 85.00. Откройте
   публичный `/api/v1/hackathons/{id}/cases/{case_id}/leaderboard` и
   `/api/v1/notifications` в Swagger, подставив ID из файла результатов.

Результат скрипта: `.local/stage7-demo.json`. В нём IDs, итог, типы
уведомлений, статусы отказов и хэш архива; пароли, токены и invite-код не
записываются. Этот файл и локальные секреты исключены из Git. Скрипт обычно
ждёт около минуты на время сервера; оставшееся время демонстрации уходит на
показ запросов и ответов Swagger.

Автоматический интеграционный тест `tests/test_journey.py` проходит тот же
путь без ожидания реального времени, используя управляемые часы и отдельный
Compose-проект. Полный набор тестов запускается командой из README.

Для воспроизведения простой проверки времени ответа выполните
`python3 scripts/check_latency.py http://localhost:8080/api/v1/hackathons`.
Это 100 последовательных запросов с выводом p95 и максимума; показатель
характеризует только локальное учебное окружение, а не нагрузочную способность.
